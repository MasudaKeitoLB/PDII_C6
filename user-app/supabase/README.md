# 管理者ログインの設定

1. SupabaseのSQL Editorで `staff-login.sql` を実行します。既存の staff_accounts の名前と pin_hash を使い、照合用関数を追加します。
2. user-app の `.env.example` を `.env.local` にコピーし、`VITE_SUPABASE_ANON_KEY` にSupabaseのpublishable key（またはanon key）を入れます。secret key / service_role key は使用しないでください。
3. user-appで `npm run dev` を実行します。起動済みの場合は再起動します。
4. ログインのお名前・管理者ID欄に staff_accounts の名前を入力します。登録済みならパスワード画面、未登録なら従来の利用者の生年月日画面に進みます。
5. 以前登録した暗証番号をパスワード欄に入力します。正解なら管理者画面に進みます。5回間違えると、そのアカウントの照合を5分間停止します。

名前の間の空白は無視します。通信・設定エラー時は画面を進めません。
管理者はページ再読み込み後に再ログインが必要です。パスワード・ハッシュはブラウザに保存しません。
接続設定がないまま利用者ログインを進めることもできません（管理者IDか判断できないため）。

## 管理者の利用者一覧について

現在の利用者データはブラウザ内の試作用データです。今回の照合はSupabase上で行いますが、Supabase Authのセッションは発行しません。実際の利用者データをサーバーに保存する場合は、別途AuthとRLSでデータ取得・変更権限を検証する必要があります。
`facility_id` は空欄で追加します。運営者が担当施設のIDを設定するまで利用者一覧は空になります。サンプルの施設IDを自動で付与することはありません。
既存のデモ用アカウント・デモパネルからは管理者認証を省略できません。
IDの存在を返す関数はログインの分岐専用なので、入力した名前が登録済みかは外部から確認できます。

SQLの権限設定の参考: https://supabase.com/docs/guides/database/functions

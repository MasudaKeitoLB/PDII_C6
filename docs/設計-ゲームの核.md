# 設計：ゲームの核（敵100体・7エリア・ボス・レア）

作成：2026-11-16　もとの文書：[世界観](世界観.md)（敵の表は5章）

## 決まっていること

- エリアは7つ。1エリア 130,000歩（道中 120,000歩＋ボス 10,000歩）。1巡り 910,000歩（1日5,000歩で約半年）
- 敵は100体：ふつう84（各エリア12）・レア7（各エリア1）・ボス7（各エリア1）・裏ボス2
- ボスは歩数のHP。歩いた分だけ減る。時間切れ・失敗なし。日をまたいでも もどらない。ボスと戦っている間は 道中の出会いを止める
- レアは 1回の出会いにつき 1/80。青天井（かならず会える仕組みは作らない）
- 出会いは 750歩ごと（今と同じ）。出会う敵は「種（seed）＋巡り（lap）＋エリア＋出会いの番号」から計算で決める
- レベルの式は `1200 + 200 × レベル`（91万歩でレベル90。レベル12の必要歩数は今と同じ 3,600歩）
- ポイント：ふつう10・レア50・ボス100・おおみそか108・はつひので365
- クリア後は「年こしの峠」：おおみそか（10,800歩）→ はつひので（36,500歩）。この間も 750歩ごとの出会いは つづける（84体から等しい確率、レアは 1/80 で7体から）
- はつひのでの あとは「ふりかえりの道」。巡りを はじめるまで 同じきまりで敵が出つづける
- 「次の巡りを はじめる」ボタンは「わたし」の画面（MeScreen）に置く。押すと lap が1ふえ、pos が0にもどる
- 画面の言い方は「敵・レベル・ポイント・たおす・ボス・レア」のまま
- 保存のキー `hoho.v2` と `version: 2` は変えない。読みこむときに 全員の game を `normalizeGame` に通す
- 古い記録は、古い式（3000 + 50 × レベル）で 累計歩数を出してから、新しい式で レベルを出しなおす

## 型とデータ

```ts
type EnemyKind = 'normal' | 'rare' | 'boss' | 'ura';
interface EnemyDef { no: number; id: string; name: string; area: 1|2|3|4|5|6|7|'end'; kind: EnemyKind; note: string }
// EnemyId = (typeof ENEMIES)[number]['id']
interface AreaDef { no: number; name: string; color: string; normals: EnemyId[]; rare: EnemyId; boss: EnemyId }
// ROAD_STEPS=120000, BOSS_STEPS=10000, AREA_STEPS=130000, LAP_STEPS=910000
// END_BOSSES=[{id:'oomisoka',steps:10800},{id:'hatsuhinode',steps:36500}]

interface GameState {
  v: 3; seed: number; totalSteps: number; lap: number; pos: number;
  level: number; exp: number; points: number;        // 画面とサーバーのために残す
  seen: Partial<Record<EnemyId, number>>;            // 会った回数（レアの記録もここ）
  pending: PendingAdventure | null;
}
interface PendingAdventure {
  steps: number; exp: number; points: number; fromLevel: number; toLevel: number; // 今と同じ
  enemies: EnemyId[];                                // ボスも入る
  boss: { id: EnemyId; left: number; total: number } | null; // 戦っている途中のボス
  clearedAreas: number[];                            // こえたエリア
  rares: EnemyId[];                                  // 今回 会えたレア
}
```

エリア・ボスの残り・次の敵・次の出会いまでの歩数は、`pos` と `seed` から計算で出し、保存しない。

## 主な関数（`src/lib/game.ts`。React・.svg・import.meta.glob を入れない）

- `fnv1a(text)`・`mulberry32(seed)`・`randAt(seed, n)`・`subSeed(seed, ...parts)`（`src/lib/random.ts`）
- `segmentAt(pos)`：いまどこか（道中・ボス・裏ボス・ふりかえりの道、エリア番号、はじまり・おわり）
- `encounterAt(seed, lap, area, j)`：j番目の出会いの敵。まず 1/80 でレア。ちがえば、ふつう12体を種で並べかえた「袋」から 12回で1まわり
- `walk(game, steps)`：区切りごとに進める。歩数が1以上なら、敵が0体でも pending を作る
- `levelFromTotal(total)`：累計歩数から レベルと経験値
- `normalizeGame(raw, ...)`：古い記録を 新しい形に直す。足りない項目は 初めの値、NaN は 0。2回通しても 同じ結果
- `newGame(seed)`・`gameAt(level, left, points, seed)`・`upcomingEnemy(game)`・`startLap(game)`

### 段階3の注意

- `EnemyId` は 段階3まで変えない（今の画面の `Record<EnemyId, …>` が型エラーになるため）
- `store.ts`：登録のとき `newGame(fnv1a(id))`、読みこみのあと 全員を `normalizeGame` に通す。変更は この2か所だけ（サーバー接続のブランチと ぶつからないように）
- `sampleData.ts` は `gameAt` に 人ごとの種を渡す。山田さん（s-yamada）の種は、次の敵が あまぐもで、2,345歩で会う3体が ふつうの敵になるものを テストで探して決める（「3体・+30ポイント」と Figma の見た目を保つ）

- `import.meta.glob` は「-small」の絵を 別の表に分ける。いしころんは 小さい絵しかないので 1.6倍にして使う

## テスト

- **単体**
  - 乱数：同じ入力で同じ値、0以上1未満
  - 出会い：同じ種なら同じ並び。まとめて歩いても 分けて歩いても 同じ結果。袋12回で ふつう12体が そろう
  - レア：種1000個・出会い160回で、そのエリアのレアに会えた割合が 86.6%±3%
  - ボス：120,000歩で はじまり、130,000歩で たおす。日をまたいでも 残りが もどらない
  - レベル：レベル12の必要歩数が 3,600。`gameAt(12, 1450)` の累計歩数が 28,550。910,000歩で レベル90
  - normalizeGame：v2 の山田さん、項目が欠けた記録、NaN が入った記録、2回通しても同じ
  - 敵の表と 世界観.md の ずれ
  - 山田さんの種で、2,345歩の3体が ふつうの敵
- **動作**：今の38項目が そのまま通る。足す3項目：
  - 39 ボスの手前まで進め、成果に「ボス…あと」が出る
  - 40 エリア1をこえ、こえたことの行と ホームの敵が変わる
  - 41 絵の無い敵が出ても コンソールのエラーが0件で、代わりの絵が出る
- **バランス**：1日5,000歩を182日。26日で13万歩（レベル31・エリア1をこえる）、182日で91万歩（レベル90・エリア7をこえる）。出会い 約1,120回、レアは 平均14回・ちがう体は 平均6.1、7体そろう見こみ 36.6%。ポイント 約12,460。峠は そのあと 約9.5日

## 危ない所

- 型を変えると 多くのファイルが同時に壊れる → 段階3を1回にまとめる
- 保存した記録が消える → version は2のまま、壊れた game も 消さずに直す
- 絵の404・NaN で 動作テスト27（コンソールのエラー0件）が落ちる → 絵が無いときは その場で描く、値は normalizeGame で確かめる
- 単体テストが React や .svg を読みこむ → game.ts と data/*.ts は 値の import だけ、絵の表は 別ファイル
- 一度に大きな歩数が入る → 区切りごとに進める（出会いの数だけ くり返す）

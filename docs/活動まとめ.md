# 活動まとめ：Figma 全画面の実装（歩歩〜HoHo〜）

対象ブランチ：`feature/all-screens`（コミット 7d3970b）／チーム CCCA405-6

## 1. 今回やったこと

Figma「PD」に描かれた全17画面を、ボタンまで動く試作として実装した。

| 区分 | 内容 |
| --- | --- |
| 利用者アプリ | ホーム（文字が非常に大きい場合を含む）、歩きスマホ防止、冒険の成果、レベルアップ、記録（1週間・1か月）、わたし（文字の大きさ・記録を見せる相手・やめる確認・目標歩数とプロフィールの変更・ログアウト） |
| 管理者画面（スマホ版） | AM-01 ログイン、AM-02 一覧、AM-03 測定結果 |
| 管理者画面（PC版） | AP-01 ログイン、AP-02 一覧、AP-03 測定結果 |
| 管理者機能 | 名前で探す、並べかえ、記録が届いていない人だけ表示、期間の切り替え、目標歩数の変更 |
| データ連携 | 利用者アプリと管理者画面は同じデータを使う。記録を見せるのをやめた人は、管理者の一覧から消え、詳細も見られない（N-14） |
| デモ | 左の確認用パネルから、サンプル利用者・歩く操作・管理者アカウントでの入室を試せる |

## 2. 進め方

1. Figma の各画面を読み出し、画面ごとに実装した。
2. 全17画面のスクリーンショットを撮り、Figma と重ねて、ずれを直した。歩数・距離・カロリー・レベル・ポイントの数字は Figma と一致した。
3. 全ボタンの動作テスト（26項目）を書いて実行した。最初は19/26件が通り、落ちたのは画面切り替え直前に数えてしまうテスト側の問題だったため、表示を待ってから確認するよう直して全件通した。
4. 前回の「登録・ログイン」のテスト（16項目）を流し直し、回帰がないことを確認した。
5. コードレビュー（エフォート：高）で10件の指摘が出た。7件を修正し、3件は試作のため見送った。
6. README を更新し、コミットして GitHub に push した。デモURLも新しい版に更新した。

## 3. 確認結果

- 動作テスト：新規26項目・既存16項目、すべて合格
- 画面のエラー・警告：なし
- Figma との見比べ：全17画面で実施

## 4. レビューで直した不具合（7件）

- 歩いている途中に別の人でログインし直すと、前の人に歩数が入っていた
- 日付が変わると、ログイン中のサンプル利用者の記録が消えていた
- いない人のログイン情報が残ったままになり、最初の画面が誤っていた
- 確認の窓を閉じたあと、操作の位置が迷子になっていた
- 送信の途中で画面が作り直される問題
- そのほか小さな不具合と、重複していたコードの整理

## 5. 今回は直していないこと（試作のため）

- 歩いている間、データを0.5秒ごとに保存している
- 紺色の画面かどうかを、画面ごとではなく一か所の一覧で決めている
- 管理者のログインがブラウザの中だけで確かめられ、パスワードもコードに入っている。本実装ではサーバー側で確かめる必要がある（READMEにも記載）

## 6. Figma の代わりにしたところ

作業中に Figma からの読み出しが Starter プランの上限に達したため、次は近い絵や形で代用した。

- AM-01 の上の背景の帯：ホームの背景の一部
- AP-01 の左の絵：はじめの画面の背景を広げたもの
- 虫めがね・▲▼・「！」の印：CSS で描いた形

## 7. チームで確かめたいこと（試作で決めた案）

- 冒険のきまり：1歩＝経験値1。次のレベルまで 3,000＋50×レベル 歩。750歩ごとに敵に1体会い、10ポイント
- カロリーの式：体重 × 歩数 × 0.00062（散歩の目安 3.5メッツに近く、Figma の数字と合う）
- 前週との差：先週の同じ曜日と比べる
- 目標歩数をだれが決めるか（16章で未決）：本人と管理者のどちらからでも変えられるようにしてある

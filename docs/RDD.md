プロジェクトデザインⅡの地域連携テーマで企業テーマ「スパーテル（てまりフィットネス）」を選び、プロジェクトテーマを「飽きをやりがいに変える長期継続モデルの構築」とした。これらの問題は、運動が義務感で行われていて、本人が自分から取り組む動機を持ちにくいことから起きていると考えた。

## 3. 目的と目標

てまりフィットネスの目的は、利用者の活動量の把握を通して健康寿命を伸ばすことである（チーム要件）。このシステムは、義務感による半強制的な運動から自分から行う運動への転換を促し、自宅での活動量を施設やケアマネージャーと客観的なデータで共有できるようにする。

### システムの概要

歩くだけで歩数と位置情報を記録し、活動量を見える化するRPG型のアプリである。歩くと2Dのドット絵で描いた主人公が進み、敵が出てくる。敵を倒すと経験値とポイントが手に入り、経験値がたまるとレベルが上がる。

主人公の成長を見ることで、自分から運動を続ける気持ちを保てるようにする。利用者が使うアプリと、施設の管理者・スタッフやケアマネージャーが見る管理者画面は、同じデータを使う。

### 目標値

| 項目 | 現状値 | 目標値 |
| --- | --- | --- |
| 1日あたりの歩数（65歳以上） | 男性5,597歩／女性4,726歩 | 男性7,000歩／女性6,000歩 |
| アプリの操作に難しさを感じない高齢者の割合 | 41% | 100% |
| 自宅での活動量の把握 | 把握できていない | ケアマネージャーが把握できている |
| 高齢者向けの運動継続アプリ | 簡単に使えるものがない | 簡単に使えるものがある |

出典はレポート表2.1で、ポスターの丸めた値（男5000／女4000歩）は使わない。自宅での活動量は、ケアマネージャーに加えて施設の管理者・スタッフも把握できる状態を目指す（10/14確認）。確かめ方は15章にまとめた。

### 既存のサービスとの違い

- 利用者が楽しむだけでなく、施設の管理者・スタッフやケアマネージャーが利用者の運動量を確認できる
- 順位を競うのではなく、いろいろな世代が協力して続ける（サブMVP）
- 高齢者が使うことを前提に、画面と操作を設計する
- 歩いている間は操作できないようにして、歩きスマホを防ぐ

ポスターセッションの相互評価（2026年7月7日、17人）では、「高齢者に合っているのか」「ポケモンGOなどと何が違うのか」という意見が出た。上の4点は、この2つの疑問への答えにもなる。

対象は、てまりフィットネスを利用する65歳以上の高齢者で、スマートフォンを少しでも触ったことがある人とし、解決方法は情報システムに限る。

- スマホの経験：スマートフォンを少しでも触ったことがある人（チーム要件）。レポートでは「スマートフォンを持っていて、アプリ内の操作ができる人」としていた
- 興味関心：スマートフォンを使うことに興味がある人（レポート）
- 解決方法：情報システムによる解決であること（レポート）
- 端末：利用者が持っているAndroidのスマートフォンとiPhone（チーム要件）
- スマートフォンを持たない人には、紙媒体との併用で対応する。具体的な方法はまだ決まっていない（16章）

### 開発で気をつける制約

- 今期の試作はMVP（メイン機能）に絞る（10/14確認、チーム要件）
- 歩数と位置情報は、利用者本人のスマートフォンで計測する（案）
- 利用者のスマートフォンは機種もOSもさまざまなので、特定の機種だけを前提にしない（案）
- アプリから操作を止められるのは歩歩の画面だけで、スマートフォン全体は止められない。歩きスマホ防止（M-11）はこの範囲で作る（案）

## 7. 利用の流れ

利用者は最初の設定だけ施設で済ませれば、あとはスマホを持って歩くだけで記録が残り、管理者側はそれを管理者画面で確認する。各手順は資料をもとに想定した流れで、細かい部分は設計で変わりうる。

### 利用を始めるまで

1. てまりフィットネスのスマホ教室で、スタッフと一緒にアプリを入れる
2. 名前と誕生日を登録し、身長・体重と1日の目標歩数を決める。次からは名前と誕生日でログインできる
3. 歩くと主人公が進むことと、歩いている間は操作できないことを、スタッフと一緒に確かめる（サブMVPではチュートリアルで説明する）
4. てまりフィットネスと担当のケアマネージャーにデータを共有することに同意する

### ふだんの1日

1. スマホを持って散歩や買い物に出る。アプリを開いていなくても、歩数はバックグラウンドで記録される
2. 歩いている途中でアプリを開くと「立ち止まってから操作してください」と表示され、操作できない
3. 立ち止まってアプリを開くと、歩いた分だけ主人公が進み、出てきた敵を倒して経験値とポイントが手に入る
4. 経験値がたまると、主人公のレベルが上がる
5. ヘルス画面で、自分の歩数・移動距離・消費カロリーの推移を、1週間・1か月など見たい期間で確かめる

### 管理者側の確認

1. 施設の管理者・スタッフ、またはケアマネージャーが、自分のアカウントで管理者画面にログインする
2. 利用者の一覧から1人を選ぶ。施設の管理者・スタッフには施設の利用者が、ケアマネージャーには担当する利用者だけが表示される
3. 本日の歩数と前週との差、移動距離、消費カロリー、歩数の推移を見る。推移は1週間・1か月など、見たい期間を選べる
4. 自宅での活動量を、運動の声かけやケアプランを考えるときの材料にする

### サブMVPを追加したあと

1. フレンドや、地域の人も参加できる協力コミュニティの仲間と、期間限定のイベント（クエスト）に挑む
2. 敵を倒して手に入れたアイテムやスキンで、主人公の見た目を変える
3. たまったポイントでガチャを回したり、地域の店舗で特典と交換したりする
4. イベントの開始や目標の達成を、通知で知る

## 8. システムの全体像

利用者のスマホで記録した歩数はサーバーに集まり、共有に同意した利用者の分だけが管理者画面に表示される。

（図の内容）

- 利用者のスマホ（歩歩アプリ）：歩数・移動距離・消費カロリーを記録する／歩くと冒険が進む2DドットのRPG／自分の歩数の推移を見る／歩いている間は画面をロックする
    - ↓ 歩数・移動距離・消費カロリーを送る（通信はSSL/TLSで暗号化）
- サーバー：利用者情報と日ごとの記録を保存する／共有と同意の記録を持つ
    - ↓ 共有に同意した利用者の分だけ
- 管理者画面：施設の管理者・スタッフとケアマネージャーが見る／利用者の一覧と測定結果（期間を選べる）／形は未決（アプリ内か、PC向けのWeb画面か）
- 運営者（開発チーム）：アカウントを発行する（→サーバー）
- サブMVPで加わる部分：地域の参加者（フレンド・協力コミュニティ）、地域の店舗（広告を出す・ポイントと特典を交換）

## 9. 機能要件（MVP）

MVPでは、チームが「必ず実装したい機能」とした、歩くと進むRPG、歩数・移動距離・消費カロリーの記録と推移、管理者画面、歩きスマホ防止、高齢者でも使えるログインを作る。

| ID | 機能 | 要件 | 根拠 |
| --- | --- | --- | --- |
| M-01 | 利用者登録 | 名前、誕生日、ニックネーム、性別、身長、体重、1日の目標歩数を登録できる。入力は1画面に1項目とし、スマホ教室でスタッフと一緒に入力できるようにする | チーム要件（名前・誕生日）、追加（案） |
| M-02 | ログイン | 名前と誕生日でログインできる。一度ログインした端末では、次から入力しなくても使えるようにする（案） | チーム要件 |
| M-03 | 歩数の測定 | スマートフォンのセンサーで歩数を数え、日ごとに記録する。アプリを開いていない間もバックグラウンドで計測する | チーム要件、レポート4.2 |
| M-04 | 移動距離の算出 | スマートフォンで1日の移動距離を出す。位置情報を使うか、歩数と歩幅から出すかは設計で決める | チーム要件、レポート4.2、図4.2 |
| M-05 | 消費カロリーの算出 | 歩数や運動量、体重などから1日の消費カロリーを計算する | チーム要件、図4.2 |
| M-06 | データの送信 | 記録した歩数・移動距離・消費カロリーをサーバーに送る。通信できないときは端末に保存し、つながったときに送る | チーム要件（通信環境・オフライン対応） |

## 14. 運用

導入はてまりフィットネスのスマホ教室を入口にし、スタッフと一緒に利用者登録とデータ共有への同意まで済ませる。

- スマホ教室：施設側でスマートフォン教室を開き、アプリの入れ方と使い方を教える。チームの課題にある「スマホ操作の上達」につなげ、高齢者同士が教え合える場にもする（チーム要件、レポート4.1、図4.1）
- 導入の手伝い：名前と誕生日の登録、ログイン、データ共有への同意を、スマホ教室の中でスタッフと一緒に行う（追加・案）
- 管理者画面の説明：施設の管理者・スタッフとケアマネージャーに、管理者画面の見方を説明する（追加・案）
- 紙媒体との併用：スマートフォンを持たない人も参加できるよう、紙媒体を併用する。方法は未決（レポート4.2・第5章、16章）
- 費用：サーバーなどの費用は、広告収入でまかなう（チーム要件、ポスター⑥、サブMVP）
- 意見の集め方：試作を使ってもらったあと、てまりフィットネスの利用者とスタッフから意見をもらう（レポート4.3）

## 15. 検証の方法

MVPの試作では、まず歩数の精度と操作のしやすさを確かめる。歩数そのものが増えたかどうかは、長く使ってもらってから確かめる。

| 確かめること | 方法 | 目安 | 時期 |
| --- | --- | --- | --- |
| 歩数の精度 | スマホで数えた歩数と、実際に数えた歩数を比べる | 許容範囲はチームで決める | MVPの試作中 |
| 操作のしやすさ | 高齢者に試作を使ってもらい、アンケートで「難しくない」と答えた人の割合を見る | 100% | MVPの試作後 |
| 自宅での活動量の把握 | 施設の管理者・スタッフとケアマネージャーに管理者画面を見てもらい、利用者の様子が分かるかを聞く | 把握できている | MVPの試作後 |
| スマホ操作の上達 | スマホ教室の前と後で、ひとりでできる操作（ログイン、推移の確認など）が増えたかを見る | チームで決める | MVPの試作後 |
| 1日あたりの歩数 | 使い始めた直後と一定期間後で、1日の平均歩数を比べる | 男性7,000歩・女性6,000歩 | 長く使ってもらった後 |
| 続けて使えているか | 使い始めてから一定期間後も使っている人の割合を見る | チームで決める | 長く使ってもらった後 |

「スマホ操作の上達」と「続けて使えているか」はレポートにない指標で、チーム要件の課題とテーマの「長期継続」を確かめるために追加した（案）。

## 16. 未決事項

次の17項目は資料だけでは決まらないため、チームで決める必要がある。決まったものからチェックを入れていく。

- [ ]  管理者画面の形：スマホアプリの中で切り替えるか、PC向けのWeb画面にするか。施設の管理者・スタッフのように多くの利用者を見る場合は、Web画面のほうが一覧で見やすい→スマホ画面
- [ ]  管理者側の見られる範囲：施設の管理者・スタッフは施設の利用者全員、ケアマネージャーは担当の利用者だけ、という案でよいか
- [ ]  ログインの安全性：名前と誕生日だけでは他人もログインできてしまう。一度ログインした端末では入ったままにする、簡単な暗証番号を足す、などの対策→好きなローマ字一文字入れる
- [x]  RPGの進み方と歩きスマホ防止の両立：歩いている間は画面をロックするので、歩いた分の冒険を、立ち止まって開いたときにまとめて見せるか→成果だけを画面に表示
- [ ]  敵との戦い方：歩数に応じて自動で進めるか、立ち止まってから操作するか
- [x]  レベルアップの条件：1日の目標を達成したら上がるか、累計の経験値で上がるか。累計にすると、目標に届かない日でも少しずつ育つ→経験値持ち越し
- [x]  目標歩数（規定歩数）を誰が決めるか：本人、施設のスタッフ、ケアマネージャーのどれか。最初から男性7,000歩・女性6,000歩にせず、体の状態に合わせる案もある
- [ ]  位置情報の使い道：移動距離の計算だけに使うか、決まった場所に行くクエストなどにも使うか。管理者側にどこまで見せるか
